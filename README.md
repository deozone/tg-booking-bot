# Телеграм-бот записи клиентов

Бот берёт на себя запись: клиент за минуту выбирает услугу, мастера, день и время,
подтверждает и получает напоминание утром в день визита. Администратор видит новые
записи и отмены сразу в Telegram и может смотреть расписание дня одной командой.

Пример настроен на барбершоп, но услуги, мастера и график лежат в одном файле
[`bot/salon.json`](bot/salon.json) — переносится на маникюр, автосервис, репетитора или
медцентр правкой конфига, без изменений в коде.

## Что умеет

**Клиент**

- запись за 5 нажатий: услуга → мастер → дата → время → подтверждение;
- «любой мастер» — показывает объединённое свободное время всех подходящих мастеров
  и назначает конкретного человека при подтверждении;
- свободное время считается по-настоящему: учитываются смена мастера, длительность
  услуги, уже занятые часы и запрет записи «через пять минут»;
- телефон берётся кнопкой из Telegram, повторно не спрашивается;
- «Мои записи» с отменой;
- напоминание утром в день визита.

**Администратор**

- уведомление о каждой новой записи и отмене: время, услуга, мастер, имя, телефон;
- `/today` — расписание на сегодня с итоговой выручкой;
- `/week` — то же на неделю вперёд;
- `/id` — узнать свой Telegram ID для настройки.

## Как устроено

Бот живёт на бесплатном serverless-вебхуке: Telegram присылает апдейт, функция
просыпается, отвечает и засыпает. Постоянного процесса нет, поэтому:

- **состояние диалога — в кнопках.** Услуга, мастер, дата и время закодированы в
  callback-данных, поэтому боту не нужно помнить, на каком шаге клиент;
- **данные — во внешнем хранилище.** Redis (Upstash) по HTTP на проде, JSON-файл при
  локальном запуске. Интерфейс один — `bot/storage.py`;
- **двойной записи на одно время не будет.** Каждая клетка расписания занимается
  атомарно (`SET NX`): если два человека жмут одно время одновременно, второй получит
  «время только что заняли», а не запись поверх чужой.

| Файл | Отвечает за |
| --- | --- |
| `bot/salon.json` | услуги, мастера, график, глубина записи — правится под клиента |
| `bot/config.py` | разбор и проверка конфига |
| `bot/schedule.py` | календарная арифметика: какие начала услуги влезают в смену |
| `bot/booking.py` | брони, отмены, занятость, индексы по клиенту и по дню |
| `bot/storage.py` | Redis по HTTP и JSON-файл за одним интерфейсом |
| `bot/handlers.py` | сам диалог |
| `bot/keyboards.py`, `bot/texts.py` | кнопки и тексты |
| `app.py` | точка входа на Vercel: вебхук и утренние напоминания |

## Локальный запуск

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env        # вписать BOT_TOKEN от @BotFather
python run_polling.py
```

В этом режиме хостинг не нужен: бот сам опрашивает Telegram, записи складываются в
`data/bookings.json`.

## Деплой на Vercel

1. Залить репозиторий на GitHub и импортировать проект в Vercel.
2. Storage → создать базу Upstash Redis и подключить к проекту (переменные
   `UPSTASH_REDIS_REST_URL` и `UPSTASH_REDIS_REST_TOKEN` подставятся сами).
3. Добавить переменные `BOT_TOKEN`, `ADMIN_IDS`, `WEBHOOK_SECRET`.
4. После деплоя переключить бота на вебхук:

```
python set_webhook.py https://ваш-проект.vercel.app/api/webhook
```

Напоминания включены в `vercel.json`: `/api/cron` дёргается ежедневно в 06:00 UTC
(09:00 по Москве). Вернуть бота на локальный режим — `python set_webhook.py --off`.

## Тесты

```
.venv\Scripts\pip install -r requirements-dev.txt
python -m pytest
```

25 тестов: расписание (услуга не вылезает за смену, выходные, запрет записи впритык),
брони (пересечения по длительности, повторная бронь того же времени, отмена
освобождает время), сквозной прогон диалога на подменённой сессии Telegram — от
`/start` до отмены записи, прод-хранилище против игрушечного Redis-REST сервера и
точка входа (чужой запрос без секрета не проходит, битое тело не роняет функцию).
